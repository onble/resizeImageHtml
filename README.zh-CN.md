# 图片缩放工作台

[English](README.md)

需要块状像素化效果时，使用独立的 [Pixel Studio 项目](pixelImage/README.zh-CN.md)，运行其 `pixelImage/start.cmd`（端口 4180）。子工具配置与目录独立，本 Resize Studio 继续使用 LANCZOS。

## 界面语言

页面右上角的 EN / 中文 下拉框可即时切换。首次打开默认英文，语言选择保存在当前浏览器，刷新后继续生效；与暗黑模式独立记忆。按钮、说明、预览、错误提示和已有处理记录一起切换，已选素材、尺寸参数、文件名和目录路径保持不变。批量导出期间暂时禁用语言选择。项目默认 README.md 使用英文，本文件保留中文说明。

双击 **start.cmd** 启动。服务在后台运行，并自动用默认浏览器打开 `http://127.0.0.1:4178`。重复启动时，只有协议和构建版本都与当前文件相符才会复用服务；旧服务必须通过 PID、项目命令行和监听端口共同验证后才会重启。无法确认归属的进程保持运行，并显示具体错误。双击 **停止工具.cmd** 停止后台服务。

需要 **Node.js 20 或更新版本，以及 Python 3.10 或更新版本和 Pillow**，不用 `npm install`，没有构建步骤。启动预检会检查依赖，并通过 Python 实际处理一张内置小 PNG，成功后才认为服务就绪；服务进程开始监听前也会执行此项检查，包括通过 `npm start` 启动时。自检不写入用户输入/输出目录，也不自动安装依赖。也可运行 `npm start`（关闭终端停止服务）。**不要直接双击 index.html**，图片处理和目录读写依赖本地服务。

显式设置 `RESIZE_IMAGE_PYTHON` 时使用指定解释器；否则依次查找项目 `.venv`、`py -3` / `python3` / `python`，最后回退到 Codex 自带运行时。运行 `node image-processor.mjs --check` 可以单独检查选中的运行时、协议和构建标识。

站点图标位于 `public/favicon.svg`，浏览器标签和页面左上角共用此图标，采用蓝色背景、白色图片轮廓和缩小箭头。

## 视觉主题

采用蓝色主操作与中性灰素材工作区：主色 `#355CE5` 用于导出、选中、焦点和进度；白色卡片与 `#F5F6F8` 浅灰页面承载内容；`#1F2937` 深灰用于正文。主导出按钮可用时为蓝底白字，禁用时为灰底灰字，避免仅降低整体透明度而显得发黄。缩略图和预览的透明棋盘格使用中性灰，便于判断素材颜色。成功与错误状态分别使用独立的绿/红提示色。

颜色集中在 `public/styles.css` 的 `:root` 变量中；更新主题时同时调整 SVG 图标。

页面右上角可点击「暗黑模式 / 浅色模式」即时切换，选择保存在当前浏览器的 localStorage，刷新后仍然生效。首次使用默认为浅色。暗黑模式保留蓝色主操作，使用深灰背景与浅色文字；素材棋盘格、输入框、预览弹窗和按钮状态一起适配。主题只改变界面显示，不改变导出的图片颜色或 JPG 白色背景。

## 日常操作

1. 拖入多张图片或文件夹；也可使用「选择图片」「导入文件夹」。导入素材自动勾选，重复导入同一批文件不会重复添加。
2. 素材目录默认为本项目的 `./input`。使用「浏览」或输入路径后点「加载」切换目录，支持相对路径和绝对路径。在缩略图左上角选择需要处理的图片，点击图片预览。首次加载/切换目录的已有素材默认不勾选；运行期间检测到新增图片会自动勾选。
3. 点击缩放方式，填写尺寸或百分比；常用数值有快捷按钮。搜索后「全选可见」只选当前搜索结果，「取消选择」取消全部选择。
4. 填写目标文件夹，点击「批量处理并导出」，然后「打开输出文件夹」。支持中文文件名、中文目录和多级子目录。

素材列表上方的「全选可见」「取消选择」「清空拖入素材」采用图标加文字按钮，适配浅色／暗黑主题。清空拖入素材只移除列表中的导入项，不删除原图。

「恢复默认参数」按钮会明确切换到按高度 120、PNG、LANCZOS、开启 PNG 优化、关闭调色板。已移除的最近邻偏好会从浏览器历史设置中删除，其它已保存偏好继续保留。预览和处理记录显示后端实际使用的采样方式与调色板状态。结果预览默认 1:1，可切换为适应窗口；比较时应使用同一原图、尺寸、参数和显示比例。

## 缩放按钮

| 功能 | 行为 |
| --- | --- |
| 按高度 | 固定高度，宽度等比计算；如 120×600 → 高度 300，得到 60×300 |
| 按宽度 | 固定宽度，高度等比计算 |
| 指定尺寸：拉伸 | 强制指定宽高，适合明确需要 108×108 等尺寸的情况 |
| 指定尺寸：留白 | 等比缩放，居中放入固定画布；PNG/WebP 留白透明 |
| 指定尺寸：裁切 | 等比缩放铺满固定画布，居中裁掉多余部分 |
| 按百分比 | 50% 为半尺寸，80% 为原尺寸的 0.8 倍 |
| 限定范围 | 等比放进最大宽高范围，输出实际尺寸，不补画布 |

默认不允许放大；需要放大时勾选「允许放大」。所有尺寸模式、缩略图、预览和导出统一使用 Pillow LANCZOS，不再提供「像素风/最近邻」开关，后端也会忽略旧请求中的 `nearest`。本项目内置逐字节未修改的原始缩放脚本 `python/resize_image.py`，并使用 `python/resize-source.json` 中记录的 SHA-256 校验副本，不依赖外部项目目录。原脚本的 `--nearest` 定义保持不变，工作台不会启用它。默认 PNG 的按高度、正方形拉伸直接调用原脚本 `resize_png`；按宽度、百分比、限定范围、留白、裁切及非正方形拉伸是工作台在 Python 中的适配，不是原命令行已有的全部模式。其它等比结果满足原函数尺寸规则时也可走原入口。

前端仅负责交互与显示，尺寸计算、输出命名、缩略图、预览、导出全部由本地后端处理；不再保留 Canvas 处理或前端尺寸算法。比例尺寸在 .5 处采用 Python 的取整规则。已有工具及其文件保持不变。

缩小像素尺寸仍会丢失细节。目标尺寸很小时，细描边仍可能不足一个像素。PNG 无损优化仅减少编码体积，无法恢复缩小中损失的细节。

## PNG 无损优化

输出格式为 PNG 时，「PNG 无损优化」默认开启，可手动关闭，选择随尺寸参数一起记忆。JPG/WebP 隐藏此选项，也不执行 PNG 优化。

原始缩放入口使用 `optimize=True, compress_level=9` 编码 PNG，优先保留其完整编码结果；即使基础 PNG 体积相同或更小，也不会静默替换原编码。无节省时记录为原始编码、节省 0。Python 扩展路径使用相同 Pillow 参数，仅接受更小的优化候选。原入口/优化异常或优化超过 30 秒时，在能够生成基础 PNG 的情况下回退并继续导出。

「256 色 PNG 调色板 · 有损」是独立可选开关，对应原脚本的 `--palette`，默认关闭。它可能改变颜色和透明度；PNG 无损优化只指缩放及所选调色板转换之后的编码，不代表缩放或调色板转换无损。

前后预览使用同一处理流程，标注最终文件体积。处理记录显示每张图片的优化前后体积、节省大小和比例，并统计本批实际保存文件节省的体积；跳过和失败文件不计入。批次逐张处理，停止可取消当前请求并避免写入尚未导出的图片，已保存文件保留；关闭预览会取消其处理请求。

这里的无损指缩放完成后不再改变像素；缩放本身仍会改变图片。旧版 OxiPNG 文件与[第三方许可证](public/vendor/oxipng/NOTICE.md)保留在仓库中，应用已不再运行这些文件，也不通过 HTTP 提供访问。

## 输入目录监听

勾选「监听目录变化」后，页面打开期间每 3 秒扫描一次，递归加载新增/更新图片、移除已经删除的图片，保留未改变素材的勾选状态。导出时暂停刷新，避免同一批素材被中途替换。此功能更新素材列表，**不自动导出**。浏览器后台可能降低定时器频率，回到页面后可点「立即刷新」。关闭页面后不继续扫描。

运行期间新增图片会自动勾选并优先排在列表前面：新素材按检测/导入时间倒序，同一批时间相同的按名称升序（数字按数值排序）；已有素材按文件修改时间倒序、同一时间按名称升序。复制进来的老图片也会以本次加入的时间优先显示。手动取消勾选后，后续刷新不会重新勾选；原文件被更新时保留当前选择和加入时间。切换目录视为首次加载，新目录已有素材不会全部自动勾选。

拖入文件夹是一次性导入；若要持续同步，请在「素材目录」中选择这个目录。资源选择用缩略图窗口和搜索完成，无需把所有素材都处理一遍。`.meta` 和其他非图片文件会被忽略。

## 输出目录与原图

- 默认输入为 `./input`，默认输出为 `./output`，都以 `resizeImageHtml` 项目目录为基准解析，不依赖启动时的工作目录。移动整个项目后仍可使用。
- **保留原 Python 工具及其 input/output，不移动、不清空。** 当前工具默认使用自己的 input/output。
- 指定目标目录后直接优先写入该目录，支持相对路径或绝对路径；留空恢复 `./output`。目录不存在时自动创建。页面修改素材目录的功能继续保留。
- 输入目录、输出目录和监听开关保存在 `settings.json`；尺寸等选项保存在当前浏览器的 localStorage。
- 默认保留子目录结构。手动导入/拖入文件夹时保留顶层文件夹名；监听目录的素材以所选目录为根保留内部结构。取消勾选后全部平铺输出。
- 同名处理默认自动加 `_1`、`_2`，也可跳过或明确选择覆盖。覆盖仅作用于目标文件；已导入的目录原图受保护。**请把导出目录放在素材目录外**。拖入文件无法获取绝对源路径，避免把导出目录选到原图所在目录，尤其在选择覆盖时。
- 支持导入 PNG/JPG/WebP/BMP。导出 PNG/WebP/JPG，转换后使用正确扩展名。PNG/WebP 保留透明，JPG 用白色背景。WebP/JPG 支持质量设置。
- 暂不迁移原 Python 工具的 Excel 尺寸映射；GIF 动画和 TIFF 不在本版支持范围。
- 「指定大小」指像素宽高，不是指定 KB/MB；若需要文件体积目标，可作为后续功能扩展。

浏览器负责界面、上传原图到本地服务以及显示处理结果，不再通过 Canvas 缩放或编码输出图片。Python/Pillow 负责实际缩放和编码，Node.js 负责安全接口、目录操作和最终原子写入。本地服务只监听 `127.0.0.1`，保留 Host/Origin、请求令牌、路径和符号链接检查；图片不上传到互联网。单张导出数据上限 80 MB，输出单边上限 16384 px，总像素上限约 3200 万，批次逐张处理。停止任务后，已保存的文件保留。

## 验证与排错

运行 `npm test` 检查尺寸计算、Python 真实图像处理与解码像素、路径约束、目录扫描、同名处理和接口访问限制。文件写入测试使用临时目录；预览、尺寸、透明度、目标文件及原图保留还需单独进行浏览器验证。启动脚本日志位于 `.runtime/server.log` / `.runtime/server.error.log`。

如果所有缩略图都提示 fetch 失败，刷新后页面也无法打开，重新运行 **start.cmd**；启动失败时查看 `.runtime/server.error.log`。仅能打开页面不代表图片处理正常，后台就绪需先通过真实图片处理自检。

Windows 下，在探测 Python 前先短暂启动当前 Node 可执行文件，初始化子进程 JobObject，避开旧版 libuv 与 Windows Store 程序别名相关的 `AssignProcessToJobObject: (87)` 问题（[上游说明](https://github.com/libuv/libuv/pull/4152)）。此兼容处理不依赖升级系统 Node，也不改变图片处理算法。

针对提供的 `cardIcon.png` 原图，已核验原脚本生成的 150×150、LANCZOS、RGBA PNG 与工作台结果编码字节完全一致。看到不同效果时，应先核对实际参数和显示比例，不能直接据此认定 PNG 算法不同；后续比较继续使用同一原图、同一参数及 1:1 结果预览。

端口占用时使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 4179`。网络盘需确保当前 Windows 用户可访问；报错会显示在处理记录中。
